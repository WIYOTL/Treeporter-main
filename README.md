# Treeporter — Simple. Rapide. Treeporter.

**Envoyez vos fichiers vers GitHub sans commandes Git complexes ni terminal.**

Treeporter est une application web open source qui simplifie l'envoi de fichiers, de dossiers entiers et d'archives ZIP vers un dépôt GitHub, grâce à une interface simple et accessible.

- 📁 Envoyez des fichiers individuels ou des dossiers complets.
- 🗜️ Importez des archives ZIP.
- 🌳 Conservez l'arborescence de vos fichiers.
- 📱 Utilisez Treeporter depuis un appareil compatible.
- ⚡ Simplifiez votre workflow GitHub sans passer par le terminal.

## 1. 🧑‍💻 Pour les développeurs : lancer Treeporter en local

Prérequis : Node.js 18+ et npm (sur ton Mac/PC).

```bash
cd treeporter
npm install
npm run dev
```

Le terminal affiche deux adresses :
- `Local: http://localhost:5173` → à ouvrir sur l'ordinateur pour un premier aperçu rapide.
- `Network: http://192.168.x.x:5173` → à ouvrir **dans Safari sur ton iPhone**, à condition que l'iPhone et
  l'ordinateur soient sur le **même réseau Wi-Fi**.

⚠️ Sur cette adresse réseau locale (http, pas https), tu peux tester toute l'interface et le **mode démo**
normalement, mais le service worker (cache hors-ligne) ne s'enregistrera pas — c'est une restriction des
navigateurs, pas un bug. Pour une vraie installation PWA complète, passe à l'étape 2.

## 2. Déployer une version PWA en HTTPS

Le service worker et l'ajout à l'écran d'accueil dans de bonnes conditions demandent du HTTPS. Le plus simple,
gratuit, sans configuration serveur :

```bash
npm run build
```

Cela génère un dossier `dist/`. Dépose-le sur l'un de ces hébergeurs statiques gratuits :
- **Cloudflare Pages** ou **Netlify** : glisser-déposer le dossier `dist` sur leur interface web (aucune ligne de
  commande nécessaire).
- **Vercel** ou **GitHub Pages** : fonctionnent aussi très bien si tu les utilises déjà.

Tu obtiens une URL `https://....` — c'est celle-là que tu utiliseras au quotidien sur ton iPhone.

## 3. Installer sur l'écran d'accueil de l'iPhone

1. Ouvre l'URL (locale ou déployée) dans **Safari**.
2. Bouton **Partager** (carré avec flèche vers le haut).
3. **Sur l'écran d'accueil** → Ajouter.

L'icône Treeporter apparaît alors comme une app, en plein écran, sans barre d'adresse.

## 4. Essayer Treeporter sans compte GitHub

Le mode démo permet de découvrir l'interface sans connecter de compte GitHub.

Tu peux tester l'ajout de fichiers et de dossiers, choisir un dépôt et une branche fictifs, examiner le contenu et simuler un transfert avec une barre de progression.

La démo simule volontairement l'échec d'environ un fichier sur six lors du premier essai afin de permettre de tester la fonction « Réessayer ».

**Important :** le mode démo simule les opérations. Aucun fichier n'est envoyé vers GitHub ou transmis sur Internet.

## 5. Connexion GitHub réelle

Treeporter accepte les tokens **Personal access token (classic)** et **fine-grained**. La connexion est
vérifiée auprès de GitHub ; le type est reconnu à partir du format du token pour afficher un badge et
améliorer certains diagnostics. Cette détection ne bloque pas un token dont le format n'est pas reconnu.
GitHub recommande les tokens fine-grained lorsqu'ils conviennent à l'usage souhaité.
La vérification de connexion utilise `GET /user` et ne demande aucune permission de dépôt à un Fine-grained
PAT ; Treeporter n'utilise que l'identifiant public du compte à cette étape.

1. Sur github.com, ouvre **Settings → Developer settings → Personal access tokens** et crée le type de token souhaité.
2. Pour un token **classic**, utilise `repo` pour les dépôts privés ou `public_repo` pour les dépôts publics.
3. Pour un token **fine-grained**, choisis le propriétaire et les dépôts concernés, puis accorde les droits nécessaires :
   - **Metadata: read** pour charger la liste des dépôts ;
   - **Contents: read** pour charger les branches et vérifier les fichiers existants ;
   - **Contents: write** pour transférer des fichiers et créer ou mettre à jour une branche ;
   - **Pull requests: write** si tu veux créer une pull request depuis Treeporter. GitHub peut aussi exiger
     **Workflows: write** pour modifier des fichiers de workflow dans `.github/workflows`.
4. Colle le token dans Treeporter à l'écran de connexion. Il est stocké dans les stockages locaux du navigateur
   et envoyé directement à l'API GitHub pour les requêtes authentifiées. Les droits disponibles dépendent aussi
   de l'accès du compte, de la sélection des dépôts et des règles d'organisation.

> 🔐 **Sécurité :**

> - Ne partage jamais ton jeton et ne le publie jamais dans un dépôt GitHub.

> - Accorde uniquement les permissions nécessaires à ton usage.

> - Si ton jeton est exposé, révoque-le immédiatement dans les paramètres GitHub.

> - Déconnecte-toi sur un appareil partagé et évite d'y enregistrer un jeton personnel.

> Treeporter ne transmet pas le token à un serveur applicatif : il est conservé dans le navigateur et envoyé à
> `api.github.com`. Comme tout secret accessible au code du site, il peut être lu par un script malveillant exécuté
> sur la même origine ; la persistance locale ne protège pas contre ce risque. Fine-grained PATs peuvent être créés
> sans expiration si la politique de l'organisation ou de l'entreprise ne l'interdit pas.

> Les erreurs distinguent l'échec d'authentification (`401`), les limites de débit, les problèmes réseau et les
> refus d'accès. Un `403` ou un `404` sur une opération de dépôt ne prouve pas à lui seul que le token est invalide :
> le dépôt peut être inaccessible, la permission insuffisante ou, pour une organisation, l'autorisation SSO requise.
> Les diagnostics détaillés dépendent des informations que GitHub rend disponibles au navigateur.

## Nouveautés V2.1.0

### Internationalisation complète
- Interface disponible en français et en anglais.
- Sélecteur de langue FR/EN dans le pied de page.
- Toutes les chaînes de l'interface traduites dans les deux langues, y compris les messages d'erreur, les confirmations et les métadonnées PWA.

### Authentification GitHub
- Prise en charge des Personal Access Tokens classic et fine-grained.
- Détection automatique du type de jeton à partir du préfixe (`ghp_` pour Classic, `github_pat_` pour Fine-grained).
- Affichage d'un badge correspondant (« Classic » / « Fine-grained ») une fois connecté.

### Gestion des erreurs d'authentification et d'autorisation
- Diagnostics plus précis pour les erreurs GitHub HTTP 401, 403, 404 et 429.
- Indications sur les permissions requises (Fine-grained : `Contents: Read and Write`, etc.) et les éventuelles approbations d'organisation.
- Distinction entre un token invalide et un dépôt/branche inaccessible.

### Protection des jetons
- Les PAT ne sont jamais exposés dans les messages d'erreur, les journaux ou l'interface (redaction automatique).

### Pagination complète des branches
- Récupération de toutes les pages de branches, pas seulement les 100 premières.

### Messages dédiés pour les erreurs HTTP 409, 422 et 5xx
- Messages explicites avec actions adaptées, sans affirmer de modification de dépôt non démontrée.

### Amélioration des messages d'erreur de transfert et de vérification des conflits
- Messages plus clairs avec indication des actions concrètes à entreprendre.
- Aucune résolution automatique n'est promise.

### Problème connu
- Un transfert ZIP avec un PAT Fine-grained peut rencontrer l'erreur GitHub « Resource not accessible by personal access token ». La cause n'est pas identifiée et le problème n'est pas confirmé comme résolu. Tous les Fine-grained PAT ne sont pas nécessairement concernés. Utiliser un PAT Classic ou un PAT Fine-grained avec la permission `Contents: Read and Write` sur le dépôt cible permet de contourner ce problème.

## Déploiement sur GitHub Pages (pour tester depuis l'iPhone)

Le projet est préconfiguré pour GitHub Pages via GitHub Actions : un simple `git push` build et publie
automatiquement le site.

### Étape 1 — Pousser le code sur GitHub (nécessite un ordinateur, une seule fois)

```bash
cd treeporter
git init
git add .
git commit -m "Treeporter V2.1.0"
git branch -M main
git remote add origin https://github.com/<ton-compte>/<nom-du-repo>.git
git push -u origin main
```

### Étape 2 — Faire correspondre le `base` Vite au nom exact du dépôt

Dans `vite.config.ts`, la constante `base` doit être `'/<nom-du-repo>/'` (respecte la casse). Si ton dépôt
s'appelle par exemple `treeporter`, laisse `base = '/Treeporter-main/'`. Si tu le nommes autrement, modifie cette seule
ligne avant de pousser (ou pousse une petite mise à jour ensuite).

### Étape 3 — Activer GitHub Pages

Sur GitHub : **Settings → Pages → Build and deployment → Source : "GitHub Actions"**. Rien d'autre à configurer,
le workflow `.github/workflows/deploy.yml` s'occupe du build et de la publication à chaque push sur `main`.
Le premier déploiement prend 1 à 2 minutes (onglet **Actions** du repo pour suivre la progression).

### Étape 4 — Récupérer l'URL et l'ouvrir sur l'iPhone

L'adresse sera :

```
https://<ton-compte>.github.io/<nom-du-repo>/
```

Ouvre-la dans **Safari sur l'iPhone**, puis **Partager → Sur l'écran d'accueil** pour l'installer comme PWA —
cette fois en HTTPS complet, donc avec le service worker actif (contrairement au test en réseau local).
